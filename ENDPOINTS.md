# Lestari API — endpoints used by lestari-client

> Generated by `node tools/generate-endpoints.js` from the page definitions in `js/modules/`. Do not edit by hand — change the module and regenerate.

This is the contract the HTML client expects from the Lestari backend. It covers every back-office feature of the client (80 screens, 332 endpoints). All attribute names are English `snake_case`.

## Conventions

| | |
|---|---|
| Base URL | configured in `js/config.js` → `apiBaseUrl` (default `http://localhost:8080/api/v1`). Every path below is relative to it. |
| Auth | `Authorization: Bearer <access_token>` on every request except those marked *no token required*. Tokens come from `POST /auth/login`; on `401` the client calls `POST /auth/refresh` once, then returns to the login page. |
| Branch | `X-Branch-Id: <branch id>` is sent when the user picked a branch in the top bar. Without it the server uses the user's default branch. All data is scoped to the store + branch. |
| Content type | `application/json` (UTF-8) unless an endpoint says `multipart/form-data`. |
| Dates | `date` = `YYYY-MM-DD` in the store's time zone; `datetime` = ISO 8601 with offset, e.g. `2026-11-08T10:32:00+07:00`. |
| Money | plain JSON numbers in the store currency (IDR has no decimals). Percentages are 0–100. |
| Nullable | any field not marked required may be `null`. |
| Files | export/download endpoints return the file body with `Content-Disposition: attachment; filename="…"`. Images are uploaded first with `POST /uploads`; forms then store the returned URL. |
| CORS | the client is a static site, so the API must allow its origin, the `Authorization`, `X-Branch-Id` and `Content-Type` headers, and expose `Content-Disposition`. |

### Response envelope

Single object:
```json
{ "data": { "id": 1, "name": "…" } }
```

List (all list endpoints accept `page`, `per_page`, `q`, `sort`, `order`):
```json
{ "data": [ { "id": 1 } ], "meta": { "page": 1, "per_page": 25, "total": 120, "total_pages": 5 } }
```

Report (lists plus aggregates):
```json
{ "data": [ … ], "summary": { … }, "totals": { … }, "meta": { … } }
```

Error (any 4xx/5xx). `fields` maps request attributes to messages and is shown next to the form inputs:
```json
{ "error": { "code": "validation_failed", "message": "Some fields are invalid.", "fields": { "name": ["Required"] } } }
```

| Status | When | `error.code` examples |
|---|---|---|
| 400 | malformed request | `bad_request` |
| 401 | missing/expired token, wrong credentials | `unauthenticated`, `invalid_credentials`, `two_factor_required` |
| 402 | feature needs a plugin or active subscription | `plugin_required`, `subscription_expired` |
| 403 | role lacks the permission | `forbidden` |
| 404 | not found in this store/branch | `not_found` |
| 409 | conflict (duplicate SKU, already processed) | `conflict` |
| 422 | validation | `validation_failed` |
| 429 | rate limited | `too_many_requests` |

## Core

### Authentication

#### `POST /auth/login`

Sign in as the owner or a staff member. When two-step verification is on and `otp` is missing, responds 401 with error code `two_factor_required`. *(no token required)*

**Request body** (application/json)

```json
{
  "email": "string",
  "password": "string",
  "remember_me": "boolean",
  "otp": "string? (6 digits, only when 2FA is enabled)"
}
```

**Response** 200 OK

```json
{
  "data": {
    "access_token": "string",
    "refresh_token": "string",
    "token_type": "\"Bearer\"",
    "expires_in": "integer (seconds)",
    "user": "<User>"
  }
}
```

#### `POST /auth/refresh`

Exchange a refresh token for a new access token. *(no token required)*

**Request body** (application/json)

```json
{
  "refresh_token": "string"
}
```

**Response** 200 OK

```json
{
  "data": {
    "access_token": "string",
    "refresh_token": "string",
    "expires_in": "integer"
  }
}
```

#### `POST /auth/logout`

Revoke the current tokens.

**Response** 

204 No Content

#### `GET /auth/me`

Current user, store and active branch; also drives menu permissions.

**Response** 200 OK

```json
{
  "data": {
    "id": "integer",
    "name": "string",
    "email": "string",
    "role": "\"owner\" | \"administrator\" | \"manager\" | \"cashier\"",
    "avatar_url": "string|null",
    "permissions": [
      "string"
    ],
    "store": {
      "id": "integer",
      "name": "string",
      "logo_url": "string|null",
      "plan": "string",
      "plan_expires_at": "datetime|null"
    },
    "branch": {
      "id": "integer",
      "name": "string",
      "is_head_office": "boolean"
    },
    "active_plugins": [
      "string"
    ]
  }
}
```

#### `PUT /auth/password`

Change the signed-in user's password.

**Request body** (application/json)

```json
{
  "current_password": "string",
  "new_password": "string (min 8)",
  "new_password_confirmation": "string"
}
```

**Response** 200 OK

```json
{
  "data": {
    "changed": "boolean"
  }
}
```
